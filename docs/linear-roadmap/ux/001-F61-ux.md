## User outcome

As a person working across SkooleeAI modules, I want consistent navigation and task patterns so that I can complete school work without relearning controls or searching through irrelevant modules.

The current app supplies violet branding, role shells and reusable components, but repeated local patterns and historical accessibility findings show drift. Retain recognizable branding while improving task hierarchy, contrast and predictability. A large global catalogue must not create an equally large navigation burden: teachers, families, support staff and institutional leaders need different default workspaces with shared interaction rules underneath.

## Scope

- [ ] Define design tokens for neutral surfaces, solid readable text, restrained violet actions, spacing, typography, focus and status colors.
- [ ] Specify role-based information architecture with stable primary navigation, local module navigation and enabled-module filtering.
- [ ] Standardize forms, data tables, task queues, dialogs, confirmation, skeletons, feedback and responsive page headers.
- [ ] Build documented reference compositions for staff productivity and family/student mobile tasks using synthetic data.
- [ ] Migrate priority workflows through component-level accessibility and visual regression checks rather than isolated cosmetic overrides.
- [ ] Publish ownership and contribution rules so new features reuse the system and document justified exceptions.

## Acceptance criteria

- [ ] Each supported role has a documented primary navigation with visible active state and no links to unavailable modules.
- [ ] Reference pages use shared tokens and components for headings, actions, validation, dialogs and empty states.
- [ ] Text contrast and focus visibility pass the agreed accessibility checks across default, disabled and error states.
- [ ] Forms preserve labels, help and errors consistently, and tables offer keyboard-operable selection and actions.
- [ ] Family/student pages remain usable at narrow phone width without horizontal page scrolling.
- [ ] New feature reviews identify reused components and any approved exceptions before implementation.

## UX journey

1. Identify role and task
2. Choose shared page pattern
3. Apply tokens and navigation
4. Design full state set
5. Review responsive behavior
6. Validate with real task criteria

## UX decisions

* Use violet for primary action and selected context, with calm neutral work surfaces.
* One clear primary action per task surface; secondary actions remain discoverable but quieter.
* Let roles determine navigation and density while preserving familiar control behavior.

## Interaction states

* **Empty:** Every module explains the absence of records and offers only an authorized useful next action.
* **Loading:** Use layout-matched panel skeletons while retaining navigation and already loaded context.
* **Error:** Errors explain the failed task, preserve input and offer a bounded recovery action.
* **Permission:** Hide unavailable navigation but explain direct-link denials without confidential details.
* **Success:** Confirm the real completed action with a source link; avoid generic celebration blocking the next task.

**Mobile:** Define family/student layouts from phone tasks first; staff tables use responsive priority columns or cards while retaining efficient desktop density.

**Arabic and RTL:** Use logical CSS properties, mirrored directional icons and explicit bidirectional isolation for identifiers, emails, equations and numeric values.

**Accessibility:** Require semantic controls, visible focus, keyboard parity, accessible names, adequate targets, readable contrast and reduced-motion support on reference flows.

**Suggested microcopy:**

* Changes saved. Review the updated record.
* Choose a campus to continue.

## Verification

- [ ] Complete equivalent create/edit/review actions in admissions, reports and fees and compare interaction consistency.
- [ ] Navigate a family account with only two enabled modules at phone width and increased text size.
- [ ] Switch an Arabic role shell between task list, form and dialog using keyboard only.

**Success measure:** Measure task completion and navigation errors on representative role journeys; track shared-component adoption and accessibility regressions.

## Scope boundaries

* A brand replacement or a decorative dashboard redesign disconnected from task completion.
* Displaying all global capabilities to every role or forcing mobile tables into unreadable miniature layouts.
