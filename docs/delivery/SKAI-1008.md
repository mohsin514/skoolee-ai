# SKAI-1008 [D2-02] Versioned curriculum contract (SKAI-958 addendum)

Approved plan: `docs/product-review-2026-10/d2-market-research.md` (founder approval in chat, 28 October 2026). This ticket specifies and verifies the cross-market contract. It is not a second template engine. SKAI-958 still owns paper generation, and SKAI-969 is still its prerequisite.

## Existing behaviour (SKAI-958 / SKO-500, `src/lib/school-ai/assessment.ts`)
- `curriculumDataSchema.pack` records authority, edition, language and rights (`APPROVED | UNDER_REVIEW | MANUAL`).
- `validateCurriculumApproval` already rejects curricula built only from past papers. It also requires confirmed sources and unique IDs.
- Gaps found: there is no immutable pack ID/version, no exam year kept separate from teaching year, no grade mapping, tier, marks, duration, choice or calculator rules, no source URL/date/checksum/rights scope, no expiry, no lifecycle authorization and no pin for historical output. PR #159 (SKAI-1010) adds optional pack fields to that schema for BISE Lahore. This contract is the shared shape that both board packs are meant to target.

## Contract (`src/lib/school-ai/curriculum-contract.ts`)
| Area | Fields / rule |
| --- | --- |
| Identity | `packId` (kebab-case) + `version` (integer). Approved content is never edited: any change is a new version. |
| Market | `board` (`FBISE`, `BISE_LAHORE`, `KSA_MOE`, `CAMBRIDGE`), `qualification`, `examSession`, `examYear` (YYYY), separate `teachingYear` (YYYY-YY), `gradeMapping` {boardLevel, schoolGrade}, `term`, `subject`, `tier`, `language` |
| Assessment | `outcomes[]` (assessed flag), `paper` {totalMarks, durationMinutes, sections[] {format, marks, questionCount, attempt}, calculator, rules[]} |
| Source register | per source: kind, authority, reference, issue date, edition, URL, retrieval date, SHA-256, school applicability, rights scope, permission evidence |
| Approval register | educator approver, approval date, review/expiry date, review trigger |
| Evidence gaps | `unverified[]` {field, evidenceRequest}. Any entry blocks publication and activation. |

Publication (`validateContractForPublication`) rejects:
- any unverified field
- missing rights or permission
- conflicting editions of the same kind of source
- stale review dates
- past or model papers used as the only source (they are structural references)
- an exam year earlier than the teaching year
- section marks that do not add up to the total, or more answers required than questions offered
- an unverified calculator rule
- board-specific gaps: Cambridge needs a Core/Extended tier, KSA needs a named term, Pakistan boards need a named annual session

Lifecycle (`transitionContract`): DRAFT ⇄ IN_REVIEW → APPROVED → SUPERSEDED → REVOKED. REVOKED is terminal. Approve, supersede and revoke need `canApproveCurriculum`. Every transition returns an audit entry with actor, school and timestamp.

Other functions:
- `pinContract` / `pinMatches`: assessment output stores {packId, version, SHA-256 of the content}. A later version or a changed default never matches an old pin.
- `contractMismatches`: matches board, grade, subject, exam year, tier and language exactly. One market is never served by another market's pack.
- `contractPilotEligibility`: passes the contract to the SKAI-1007 gate (`pilot-eligibility.ts`). Invalid or unverified evidence keeps the capability off.

## Tenant scope
Contracts are global, versioned reference data. They are pure functions with no DB access and no schema or migration. School adoption and storage stay in SKAI-958 (`school_id`-scoped). The audit entry carries the acting `schoolId`. Eligibility is evaluated per school/campus geography.
