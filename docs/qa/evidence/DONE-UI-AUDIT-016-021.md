## Manual browser evidence

The app was run at `http://127.0.0.1:3345` against a new PostgreSQL cluster bound to loopback and a new `skoolee_audit` database. The fixture contains only a synthetic school, campus, classes, pupil, guardian-review item, and role-specific test accounts. The browser used signed synthetic sessions; support approval and the active English session were exercised through the UI. No `.env`, remote account, shared database, or school record was used. Each PASS matrix includes 1440px desktop, 768px tablet and 390px phone images, a first-Tab focus image, and a JSON record of HTTP status, lang/dir, root scroll width, focus outline and page errors. These were current screenshots from this branch; historical checked-in screenshots were not treated as current evidence.

Validation for the Urdu label fix: `node_modules/.bin/eslint src/lib/locale/ui-messages.ts` passed, and `node --import tsx --test tests/locale/package.test.ts` passed all 8 tests. The owner Urdu phone screenshot was recaptured after the fix and visually confirms the translated label.

The English support-approval phone screenshot visually shows the shared top toolbar's account/avatar button cut off at the right viewport edge. The document reports no horizontal overflow because the shell clips the extra width. Guardian phone screenshots show the fixed bottom navigation crossing the form at the initial scroll position; the user can scroll the form to reveal obscured fields. No shell-level CSS fix was made because both behaviors originate in shared application chrome and should be triaged centrally; neither is covered by the currently open #36 changes listed in this report.

Route and locale states not listed as PASS above remain unverified even if the outer page returned HTTP 200. In particular, the group-template page and active school-approval/active-session screens in Arabic and Urdu were not captured successfully in this run.

## Shared visual and interaction checks from source

- Typography comes from Plus Jakarta Sans in `src/app/layout.tsx`; base foreground/background and brand/focus variables are defined in `src/app/globals.css`.
- Primary action purple (`#8127cf`), ink (`#1f1a23`) and muted text are used across these surfaces. Field and panel radii vary between compact controls and content cards, consistent with their role and the shared UI patterns.
- A global `:focus-visible` selector covers links, buttons, inputs, selects, textareas, summaries and tab stops. Screen-level focus styles add contrast where needed. No keyboard-only hover dependency was identified in the reviewed controls.
- The checked source includes reduced-motion rules globally. These feature screens do not define their own decorative motion; shared summary count/card behavior is covered by PR #36.
- Responsive grids stack at small widths across the locale, model, support and guardian forms. The pupil history uses a vertical ordered list. Current browser measurements show no document-width overflow in captured PASS states; visual review still found the clipped command-toolbar button because the shell hides its extra width.
- RTL ownership is explicit for locale settings, pupil history and guardian management. Owner support uses `dir="auto"` and isolates identifiers. Academic model ar/ur states were captured and rendered with RTL direction; English and group-template screens remain unverified as listed above.
