# SKO-215 support access verification

The support workflow separates vendor administration from school approval. An APP_OWNER requests tenant-scoped access and remains the recorded support actor. Only that tenant's MFA-authenticated SUPER_ADMIN can approve, reject, revoke, or review the request. Campus roles cannot approve grants.

Support grants default to read only, expire within eight hours (one hour for emergency access), name explicit domains and actions, and exclude safeguarding, clinic, counselling, and custody records. Write access is limited to school phone, contact email, and website fields. CSV export is limited to the school profile. Entering a support session closes the ordinary owner APIs; every scoped workspace read checks the live grant and writes the actual actor and grant to the platform audit log. Revocation cancels queued support actions immediately; an outbox worker sweeps expired grants every 15 seconds and cancels their queued actions even when no support page is open. Emergency requests notify school SUPER_ADMIN accounts and retain a review deadline and evidence field. Incidents retain their owner, impact, status, and closure evidence.

## Synthetic verification

The local acceptance script requires database `skoolee215` at `127.0.0.1:55415` and an app at `127.0.0.1:3015`; it refuses any other host, port, or database name. It creates random synthetic school and user rows, runs HTTP checks using MFA-authenticated APP_OWNER, SUPER_ADMIN, and CAMPUS_ADMIN sessions, then deletes its school fixtures. Audit records are intentionally retained by their append-only lifecycle and contain only synthetic actor IDs.

Run the app with explicit local `DATABASE_URL`, `DIRECT_URL`, and test-only `AUTH_SECRET`, then run `npm run test:support-access:local` and `npm run test:support-ui:local`. The API acceptance checks cover MFA, default scope, school-only approval, rejection of safeguarding access and staff exports, support-session tenant binding, blocking general owner APIs, scoped profile reads and writes, CSV export, actor/grant audit records, emergency reviewer notification and evidence, immediate revocation, open-page expiry, background expiry sweep, and cancellation of queued actions. Browser checks cover Arabic RTL, keyboard access, approval flow, active session banner, and layouts at 1440, 768, and 390 pixels wide.

Additional checks run for this change: `npx tsc --noEmit`, `npx prisma validate`, the commercial contract check, and the production build. All database activity uses the synthetic local database; no `.env` file or Supabase project is loaded.

## Review limits

The support export currently covers the school profile only. Support writes currently cover phone, contact email, and website. Other approved domains expose audited read summaries; their writes and exports remain unavailable. Emergency notices are in-app notifications to active school SUPER_ADMIN users. This verifies application behavior against a fresh local schema and does not certify deployment configuration, production notification delivery, or production data.
