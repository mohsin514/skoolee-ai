# SKO-210 — approved report versions

Reports now acquire an immutable version containing marks, grading rules and weighted results, the selected language and remarks, document identity, branding, attendance, and generated PDF bytes. Approval names that exact version. Material edits invalidate pending approval without changing the last family release. Publication, downloads, family/AI reads, and durable delivery all use the approved snapshot. Private review notes are excluded from family artifacts.

The review queue shows blockers, changes against the last approved snapshot, reviewer history, eligible selection, selected-language remarks, grading policy, PDF history, and per-channel delivery status. Authorized teachers can correct assigned drafts; only authorized reviewers approve and publish. Corrections require a family-facing reason before approval and retain predecessor history. Old family links reauthorize access and resolve to the corrected release. Staff can retrieve exact approved historical artifacts.

Delivery reuses SKO-220's durable outbox and SKO-207's live actor/relationship authorization. Recipient/channel/version determines idempotency. The worker rejects superseded versions and revoked authority before the external boundary. An uncertain provider outcome is retained for reconciliation instead of automatic resend.

- Fresh migration and synthetic recovery rehearsal passed clean provisioning, populated baseline adoption/upgrade, restore and reconciliation checks. Recovery evidence retains its required operator sign-off status; it is not a production recovery certification.
- Production build and TypeScript validation; dedicated PR CI runs migration, build and report integration tests. Existing recovery CI remains required.

## Rollout and integration

Legacy report status flags are deliberately not converted into fake version approvals. Existing reports require human review and approval before a version can be published to families. The migration does not mutate historical PDF objects or silently bless their content.

PR #18 localization and PR #21 account lifecycle are integrated from dev. Approved versions retain the full institution locale snapshot with explicitly selected report language. New reports inherit the institution language; later locale changes require a new review and never rewrite approved bytes. The review UI follows the shared locale provider. The refreshed 42-combination browser matrix uses saved user language preferences, not document-language simulation. Currency formatting and payment ledger behavior remain covered by the merged locale tests. Report API fixtures use persisted MFA-verified login sessions under the new authentication rules.

Real provider acknowledgments and operational reconciliation were not exercised. The worker boundary was tested with an injected synthetic provider. Browser coverage is a smoke/permission matrix, not an exhaustive usability audit of every role screen. The existing broader authorization suite was adapted to create approved fixtures but is separate from the 20 report tests recorded here.
