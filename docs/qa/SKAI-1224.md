# SKAI-1224: student, guardian and staff directory imports with reconciliation (QA runbook)

Archived as SKO-283. Live QA was blocked: it "needs import spreadsheets" and "the access view says not available
for the admin role". This runbook removes both blockers for the parts that exist in the product. It does not
record a QA result. QA attaches evidence to the Jira card and moves it to Done.

## What exists, what does not

| Directory | In product | Where |
| --- | --- | --- |
| Students + guardians | Yes: stage, review, reconcile, commit, reverse | `/admin` -> Students -> Bulk import (`src/components/students/bulk-import-dialog.tsx`, `POST /api/import-batches` with `kind=STUDENT_ROSTER`) |
| Staff | **No bulk import.** Staff are added one at a time from staff management | Gap: needs a product decision and its own build ticket |

Guardians are imported on the student row (`guardianName`, `guardianPhone`, `guardianEmail`, `guardianRelationship`);
there is no separate guardian-only file.

## Access: why "not available for the admin role"

`assertRosterPermission` (`src/lib/imports/roster-access.ts`) allows the import only when all of these hold:

1. The role is `ADMIN` or `CAMPUS_ADMIN` (`canConfigureCampus`). Principals, receptionists, teachers and group
   `SUPER_ADMIN` sessions without a campus are refused by design.
2. The signed-in user is still active, in the same school, role and campus as the session.
3. The school's role permissions grant `students.view` (list batches) and `students.add` (upload). If a school
   owner switched off `students` for the admin role in Settings -> Roles, the access view shows "not available".
4. A campus is resolved. A group-level session must pick a campus first.

So the QA account must be `t1-campus_admin@example.invalid` (or `t1-admin@example.invalid` with a campus
selected) on a freshly seeded lane, with default role permissions.

## Setup

1. Local app or isolated QA lane (`docs/qa/QA-ENVIRONMENT.md`), never production. Do not re-seed a shared lane.
2. Spreadsheet: `docs/qa/fixtures/SKAI-1224-student-guardian-roster.csv` (synthetic, `example.invalid` emails,
   `QA1224-` roll numbers). Open it, pick an existing active class at the campus as the default class.
3. No feature flag is needed.

## Steps

| # | Action | Expected |
| --- | --- | --- |
| 1 | As campus admin open `/admin`, Students, Bulk import, upload the fixture | Batch staged as a rehearsal; nothing saved yet |
| 2 | Review rows | Rows 2 and 3 ACCEPTED (one guardian linked to two pupils); row 4 REJECTED (bad date); row 5 REJECTED (roll number repeated in file); row 6 REJECTED (class "No Such Class Z" named, not replaced); row 7 REJECTED (missing name) |
| 3 | Fix row 4's date in the review, skip row 7 | Row re-classified; counts update |
| 4 | Commit | Receipt shows accepted, skipped, rejected counts; pupils and one shared guardian appear |
| 5 | Upload the same file again | Previously imported rows are SKIPPED (class + roll number exists), never overwritten |
| 6 | Reversal check, then reverse | Created pupils removed; a second reverse is refused |
| 7 | Denied roles: teacher, receptionist, accountant | No Bulk import; `POST /api/import-batches` returns 403 |
| 8 | Isolation: sign in as `t2-admin@example.invalid` | No T1 batches or `QA1224-` pupils visible |
| 9 | Repeat 1-2 with `?lang=ar` and `?lang=ur` at 390 px | Right-to-left, nothing clipped |
