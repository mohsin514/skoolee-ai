## Concrete gaps found and repaired during this review

1. The permission-matrix API had only authentication. It now restricts reads to existing school manager roles with current `staff.view`, and writes to a current institution owner or SUPER_ADMIN with `staff.edit`. A campus-bound ADMIN/CAMPUS_ADMIN/PRINCIPAL is read-only; `canManageMemberships` does not imply authority to change a school-wide matrix. The owner flag comes from the current account, never token claims alone. PATCH rejects cross-origin requests and nonboolean flags; disabling View clears all mutation flags. All results are private/no-store.
2. Visitors, complaints, postal records, phone calls and certificate mutations previously checked a role but ignored revoked action flags. Their existing role/campus gates now also check current front-desk add/edit/delete authority.
3. The permission panel previously swallowed load failures, used English-only copy and closed failed role copies. Its extracted replacement provides EN/AR/UR, explicit retry/readonly states, wrapping module cards, pending locks and server-acknowledged updates. A 401/403 clears the matrix until a new GET establishes current view authority. Partial-copy failures remain open with a truthful confirmed count.

The backend repairs, final 35-case production app matrix, four delegation flows and 18 permission-panel browser cases passed. The parent populated-report defect is resolved and root visually reviewed the real app output. Native browser-toolbar 200% checks also passed; the source of magnification is separately recorded from root-font and CSS layout scaling. Root owns the final issue-state decision and evidence attachments.
