# SKO-393 [019] Configurable curriculum, grading and term structures — verification 16 October 2026

The pure suite `tests/academic/model-config.test.ts` was already 6/6 and stays green.
The mixed DB + headless-Playwright suite `tests/academic/api.test.ts` was 4/5. The one
failure was the principal-builder browser test, and it was a **cross-ticket navigation
regression**, not an academic-model defect: an uncommitted console-navigation change
(deep-linking `/principal?view=…`) makes the sidebar's "Academics" group start
**expanded** whenever a child is the current view, so the test's "expand the group"
click collapsed it and hid "Curriculum & Terms" before the test could click it.

Fixed in product code only. No test assertion was weakened, added to, or deleted.

## Root cause

The Urdu label itself is present and correct (`src/lib/locale/ui-messages.ts:485` maps
`"Academics"` → `"تعلیمی امور"` and line 739 maps `"Curriculum & Terms"` →
`"نصاب اور تعلیمی ادوار"`). The principal shell resolves it server-side (`getDisplayLocale`
seeds `LocaleProvider` from `OperationalLayout`), and `RoleSidebar` translates every label
with `useUiText()`. A throwaway Playwright probe against the prepared app confirmed the
final DOM was correct:

```
[html] {"lang":"ur","dir":"rtl"}
[nav text] … تعلیمی امور / نصاب اور تعلیمی ادوار / …
```

The defect is in the sidebar group state, not in the copy or the locale.

In the working tree, `src/app/principal/page.tsx` was changed from
`useState<PrincipalView>("overview")` to `useWorkspaceView(WORKSPACE_VIEWS, "overview")`
so the console honours `?view=…` on load (the same change is present in the owner, super,
accountant, librarian and receptionist consoles). With that change, loading
`/principal?view=academic-model` sets the active view to `academic-model` **before** the
test interacts with the page.

`NavGroup` (`src/components/role-dashboard/RoleSidebar.tsx`) opens itself when it contains
the active child:

```ts
const active = group.children.some((item) => isNavigationActive(item, pathname));
const [open, setOpen] = useState(active);
useEffect(() => { if (active) setOpen(true); }, [active]);
...
onClick={() => { if (collapsed) { setOpen(true); onExpand?.(); } else setOpen(!open); }}
```

So on `/principal?view=academic-model` the "Academics" group is already expanded and
"Curriculum & Terms" is highlighted. The test then clicks the group header expecting to
*open* it; the toggle instead *closed* it, unmounting every child. Because
`RoleShell` provides `SidebarNavigationContext = true`, `WorkspaceSubnav` returns `null`
inside the console ("RoleShell owns desktop and mobile navigation"), so the sidebar child
is the **only** rendered copy of "نصاب اور تعلیمی ادوار" — once the group closed, the
label existed nowhere on the page and the click timed out.

Confirmed with a probe that logged the group's `aria-expanded` and the child's node count
before and after the click:

```
[group count] 1 [aria-expanded] true
[child count before] 1
[group aria-expanded after click] false
[child count after] 0
```

At the commit that added this suite (`c05bf7e`) `principal/page.tsx` did not read `?view=`,
so the group started collapsed and the test's two clicks worked. The regression was
introduced by the later, uncommitted `useWorkspaceView` wiring, which is required
elsewhere (e.g. `tests/authorization/access.test.ts` relies on
`/principal?view=permissions` rendering the permissions panel), so the deep-link could not
simply be removed.

## Fix

A navigation group that holds the current view now stays expanded: clicking its header no
longer collapses it. Non-active groups still toggle open/closed exactly as before, and the
collapsed 72px rail still expands on click.

```ts
onClick={() => {
  if (collapsed) { setOpen(true); onExpand?.(); return; }
  // A group holding the current view stays open: RoleShell suppresses the
  // standalone section strip, so its children are the only route back to the
  // screen you are already on. Collapsing it would hide where you are.
  setOpen(active ? true : !open);
}}
```

Rationale for this layer rather than alternatives considered:

- **Remove the `?view=` deep-link for `/principal`** — rejected: `tests/authorization/access.test.ts`
  (another ticket) navigates to `/principal?view=permissions` and expects that panel.
- **Re-enable the duplicate section strip** — rejected: `RoleShell` deliberately suppresses
  `WorkspaceSubnav` inside consoles ("RoleShell owns desktop and mobile navigation"); the
  sidebar is intended to be the single navigation surface.
- **Leave groups collapsed on the active view** — rejected: with the strip suppressed, the
  active destination would have no visible, highlighted entry, and the existing
  `aria-current` contract for sidebar children would be unreachable.
- **Keep the active group open** — chosen: preserves the auto-expand highlight (and the
  `access.test.ts` flows, which click a *non-active* "Academics" group to open it) while
  removing the papercut where clicking your current section's header hides exactly where
  you are.

## Remaining uncertainty

- The root cause was reproduced with a throwaway Playwright probe (printed URL, title,
  `html lang/dir`, sidebar visible text, and the group's `aria-expanded` / child node count
  before and after the click); that script was deleted and is not committed.
- The change is in the shared `RoleSidebar`, so it applies to every console. The only other
  suite that drives this sidebar is `tests/authorization/access.test.ts` (another ticket),
  which was **not run here** because it needs its own fixtures/app. By inspection it is
  unaffected: its `aria-current` waits target top-level items, and it opens "Academics"
  from a non-academic view (`?view=attendance`), where the group is not active and still
  toggles normally.
- "Active group cannot be collapsed" is a deliberate product judgement. If a future design
  wants the current section collapsible, the section strip (`WorkspaceSubnav`) should be
  re-enabled inside consoles instead, so a second, always-visible route to the active
  screen exists before the sidebar entry is allowed to disappear.
