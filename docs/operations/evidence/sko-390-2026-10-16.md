## Cross-ticket reconciliation

The first run failed the very first check (`APP_OWNER without enrolled privileged MFA cannot
enter support management`). Root cause: an earlier fix for SKO-376 had replaced the principal
MFA gate with `needsMfaChallenge(...) && claims.mfaVerified !== true`, dropping the
`requiresMfa(account) && !account.mfaEnabled` clause that enforces *enrolment*. SKO-376 needs
identity/ownership probes (which carry a role but no `accessVersion`) to skip the MFA gate, and
SKO-390 needs a real session for a privileged non-enrolled account to be rejected.

Both hold with the gate scoped to full sessions:

```ts
if (claims.role !== undefined && claims.accessVersion !== undefined &&
    ((requiresMfa(account) && !account.mfaEnabled) ||
     (needsMfaChallenge(account) && claims.mfaVerified !== true))) return null;
```

Re-verified after the change: `tests/memberships/access.test.ts` remains **19/19**, so the SKO-376
fix and the SKO-390 enrolment rule coexist. (SKO-376's session tokens are minted only after its
helper enrols `mfaEnabled: true`, so restoring the enrolment clause does not affect it.)

## Files changed
