## Root cause

`history()` in `src/lib/corrections/service.ts` resolved the parent's children with
`studentScope(user)` and then filtered corrections by `studentId: { in: children }`.

The corrections feature was written while `studentScope` linked a parent to a pupil by the
pupil's explicit `parentUserId` account column. The later guardians work changed
`studentScope(PARENT)` to `guardianStudentWhere`, i.e. children are now resolved **only**
through live `GuardianRelationship` rows with a current access version. The corrections
module was not updated, so a parent linked solely by `parentUserId` (the contract used by
`tests/corrections/integration.test.ts`, `tests/corrections/browser.mjs` and the fixture at
`docs/qa/evidence`) resolved zero children.

Diagnostics on the failing fixture confirmed it: seven `APPLIED` corrections existed for the
child (`student_id` set, one `MARK` with a published successor version and five `PAYMENT`),
`students.parent_user_id` pointed at the parent account, and `guardian_relationships` had
**0** rows for that child. The rows were correct; only the parent-to-child resolution was
empty. The other two assertions that expect `history.length === 0` (a not-yet-republished
mark, and a child with `parentUserId` cleared) passed trivially for the same reason, so the
empty resolution was masking the defect rather than being a separate symptom.

## Code changed

- `src/lib/corrections/service.ts` — in `history()`, a `PARENT` now resolves children through
  `studentScope(user)` (live guardian relationship) **OR** the pupil's explicit
  `parentUserId` account link. Staff and `STUDENT` scopes are unchanged; the family
  allowlist, `status: "APPLIED"` filter and `correctionReleased` publication gate are
  untouched. This restores the corrections contract without loosening the shared
  authorization policy in `src/lib/auth/policy.ts` (the guardian work intentionally removed
  the legacy fallback from `guardianStudentWhere`, which `tests/authorization/policy-current.test.ts`
  locks in — that file was not modified).

```ts
const children = await prisma.student.findMany({ where: user.role === "PARENT"
    ? { schoolId: user.schoolId, OR: [studentScope(user), { parentUserId: user.userId }] }
    : studentScope(user), select: { id: true } });
```

No DB guard host/port/database, test environment assumption, test file, or shared test
harness was changed.
