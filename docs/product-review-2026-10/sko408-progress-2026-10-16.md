### Cross-ticket defects found and fixed

- **SKO-384** — `history()` in `src/lib/corrections/service.ts` resolved a parent's children
  only through `studentScope(PARENT)`, which the later guardians work had narrowed to live
  `GuardianRelationship` rows. Pupils linked by the explicit `parentUserId` contract column
  resolved to zero children, so the family correction history was silently empty.
- **SKO-392** — `assertCommunicationTarget` (added 13 October, after the locale test) refused
  any target that named a parent without a pupil, so an institution-only notice to one parent
  could never be authorized.
- **SKO-375** — the isolated database had been provisioned from `schema.prisma`, which cannot
  emit the Postgres triggers in `20261008021000_report_versions__a_stage/migration.sql`; an
  idempotent repair script was added (`scripts/recovery/report-version-invariant-repair.sql`).
- **SKO-376** — `resolveCurrentPrincipal` applied the MFA requirement even to identity and
  ownership probes that carry no session claims, so freshly invited `CAMPUS_ADMIN`/`PRINCIPAL`
  lookup returned null; `inviteStaff` also turned any suppressed-delivery attempt into a `503`.
- **SKO-394** — not a defect: the acceptance database simply had never had
  `tests/enrollment/fixture.ts` loaded. With the fixture present the suite is 1/1.
- **Test harness** — added a local `node_modules/server-only` shim so `node:test` can import
  modules that reference `server-only` outside the Next bundler.
