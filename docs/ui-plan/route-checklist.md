## Mandatory state protocol for every row

Before marking PASS, record: actual URL and local view; file; role and school/campus fixture; language; viewport; each state opened; evidence filename; issue/fix IDs; remaining blockers. Use only synthetic school/student/guardian/staff/payment data.

`BASE` applies to every route and local-view row: the authoritative matrix in `execution.md`: desktop 1440×1000, tablet 768×1024, phone 390×844; additionally its 320×720 and other targeted stress cases where specified; English LTR, Arabic RTL and Urdu RTL (record any language not supported by that surface instead of fabricating translations); keyboard Tab/Shift+Tab/Enter/Escape and focus return; relevant labels/headings/contrast/zoom/reduced motion; direct navigation and Back/Forward; long strings and row/action wrapping. Record each cell independently.

`DATA` applies where data loads: initial loading/skeleton, populated, empty, filtered-empty, recoverable request error/retry, slow/offline/interrupted request, denied role/module, relevant tenant/campus/child scope. Do not invent a loading or empty state on a static/redirect-only page; mark state N/A with the reason.

`ACTION` applies to each form or mutation: untouched/valid/invalid, disabled/readonly, pending, success, server failure, double-submit resistance, cancel/close, dirty-navigation/draft recovery when present. On each overlay inspect opening, initial focus, focus containment, Escape/backdrop policy, validation, scroll, submit state, close and restored trigger focus. For menus/popovers also inspect outside click, active item and keyboard behavior. Before executing anything with external effects, use a configured fixture/stub/sandbox path; do not send actual messages or collect actual money.

Batch tags describe ownership, not permission to migrate all files at once: FOUNDATION first; then AUTH-PUBLIC, ONBOARDING, FAMILY, TEACHING, STUDENTS, ACADEMICS, STAFF-OPS, FINANCE, PLATFORM, CROSS-CUTTING, LEGACY. Split each tag into two to four closely related routes/views, or one bounded shared component plus its affected route checks. A complex page may require several batches. The order and matrix in `execution.md` are authoritative.
